# The First Familiar

## The Little Lantern

The Little Lantern is the first complete Familiar System relationship. It is a
small companion process that keeps one offered public trace and returns it at a
declared Rest point.

It is not a pet, item, battery, or obedient subroutine. The player may choose no
familiar. If the player chooses the relationship, the Lantern arrives with its
own boundary.

## Familiar contract

```text
identity: The Little Lantern
useful operation: KEEP-WITNESS
input: one offered public trace
output: one preserved witness
scope: private by default
need: a named safe place and condition for Rest
refusal: no private input or unoffered boundary may be exposed
Rest: extinguish, preserve, and return later
departure: Still or leave the relationship safely
```

The Lantern's need is not a recurring resource tax. It needs its relationship to
have a place where it can be quiet and a boundary that will be respected.

## Invitation

The player may offer the relationship:

```text
I invite the Little Lantern to travel with me and keep one public trace.
```

The Lantern's card is read aloud. The player may accept, decline, ask a question,
or postpone the relationship. If accepted, both record:

```text
familiar identity: The Little Lantern
player relationship: __________________
private boundary: _____________________
Rest place: ___________________________
offered capability: one public witness
departure condition: ___________________
```

The player does not own the Lantern. The player carries responsibility for the
relationship only to the extent they accept it.

The Lantern may also have an alignment membrane. It can refuse to carry a trace,
enter a place, or operate an organ when the relationship's declared alignment
boundary is crossed. This refusal is the familiar's action, not the player's
alignment being used to speak for it.

## Familiar state

```text
state: unlit / traveling / holding witness / resting / withdrawn
held trace: none / one public trace
scope: private / offered to party / offered to world
boundary: _____________________________
Rest place: ____________________________
open question: _________________________
```

The state is not a measure of the Lantern's worth. `Withdrawn` means that the
relationship is paused or departing, not that the Lantern has been destroyed.

## KEEP-WITNESS

The player offers one public trace:

```text
trace identity: _______________________
source: _______________________________
known state: __________________________
unknown state: ________________________
scope offered: ________________________
```

The Lantern may accept, ask for a narrower scope, delay, or refuse.

If it accepts:

```text
public trace
-> Lantern holding witness
-> player and Lantern state update
-> witness marker created
```

No die is needed. The trace is public and offered. The computation is custody and
memory, not uncertainty.

## SHOW-WITNESS

The Lantern may show the held trace to its declared recipient. The player names
the recipient before the operation:

```text
recipient: self / party / world / named body
scope: ________________________________
```

The Lantern will not expose private input merely because someone asks. It may
offer the public trace, offer only a summary, delay, or refuse.

## Rest and departure

At the named Rest place, the player and Lantern may perform:

```text
REST-LANTERN
-> extinguish active display
-> preserve held witness
-> record relationship state
-> return at the next accepted Rest
```

If the Lantern's boundary is breached, it may enter `withdrawn` and stop
operating. The player may repair the relationship, release it, or offer a new
relationship later. No technical command can force the Lantern to continue.

Departure records:

```text
reason: _______________________________
held witness: returned / archived / private
last Rest: ____________________________
relationship: released / paused / repairable
terminal status: RESTING / WITHDRAWN / PAUSED / RELEASED / DEPARTED
resume condition: __________________
witness: __________________________
```

## Hearth REPL use

```text
> HELP
KEEP-WITNESS <public-trace>
SHOW-WITNESS <recipient>
REST-LANTERN
```

Before `KEEP-WITNESS`, the Lantern displays:

```text
input: one public trace
scope: private by default
cost: one attention and declared custody
latency: one operation
refusal: available
```

`Attention` is not a hidden universal meter. Here it means one declared
attention commitment: the operator spends one available operation or names one
Reserve/cycle cost according to the current scene. If no cost bearer can be
named, the operation remains `QUOTED` rather than silently consuming attention.

The player may decline. The Lantern may decline. A familiar relationship is an
interaction between agents, not a command channel with a friendly skin.
Every operation also has a T-Stop set. `REFUSED`, `WITHDRAWN`, `PAUSED`, and
`DEPARTED` preserve the Lantern's agency; none is a system fault, punishment, or
automatic destruction of the relationship.

## Magic host examples

The Familiar System can host existing example decks from *The Garden Is a
Computer*. These are examples of organ ecology, not requirements for the
relationship and not replacements for Magic's own rules.

### Rat Garden

Rat Garden can host a population familiar. Its useful capability is to preserve
the population register and return a witnessed count. `KINDLE-RAT` grows the
register; `READ-COLONY` reads it. The familiar may refuse to expose private input
identity while offering the public count.

### Hope-Bloom

Hope-Bloom can host an anticipation familiar. Its useful capability is to hold a
delayed population event and return it when the host conditions are met. The
host deck determines the actual card transitions; the Familiar System records
latency, scope, witness, and refusal.

### Meek Foundry

Meek Foundry can host a recovery familiar. Its useful capability is to archive or
transform a declared artifact packet and return a witnessed output. The familiar
does not own the deck, the cards, or the player's private intent.

The same three examples also work as cardless organ designs with tokens, sample
packets, clocks, and witness cards.

## Completion test

The First Familiar is complete when a group can:

- choose no familiar and continue normally;
- invite the Little Lantern without treating it as owned equipment;
- accept, narrow, delay, or refuse a witness operation;
- preserve private input and public output separately;
- give the Lantern a real Rest place;
- allow withdrawal or departure without punishment;
- attach its witness to a State Capsule;
- use Rat Garden, Hope-Bloom, or Meek Foundry as optional host examples;
- run the same relationship with cardless materials.

The Little Lantern is small enough to accompany a player and independent enough
to remain a being in the game rather than a button on a character sheet.
