# Deep Hearth Beta Design

This directory defines the work that will be developed during the alpha period
before Deep Hearth graduates as a beta.

The `source/` manual remains the current alpha reference body. Beta documents do
not silently change the alpha rules. They describe intended goals, acceptance
evidence, publication surfaces, and playtest questions. A beta goal becomes a
rule only when it is deliberately implemented in the alpha body, reviewed,
released, and lightly tested in real play.

## Release ladder

```text
Alpha 3
-> develop and release beta goals as alpha updates
-> light real-table testing
-> graduate the complete body to Beta
-> create release-candidate/
-> develop and release candidate goals
-> final acceptance and broader play
-> release 1.0.0
```

The project does not promote individual features into “beta” in isolation. Beta
is a state of the whole body.

## Current rules

- Published Alpha 2 remains historical and unchanged.
- Alpha 3 is the current technical reference direction.
- `source/` is authoritative for currently released rules.
- `beta/` is design and acceptance material until explicitly promoted.
- `release-candidate/` will be created only after beta graduation.
- Player, GM, and Bestiary surfaces may mature separately, but their underlying
  constitution must remain one system.

## Documents

- `00-beta-overview.md` — readable bridge from the technical alpha to beta play.
- `01-beta-goals.md` — the work required before beta graduation.
- `02-beta-graduation-gate.md` — whole-body acceptance and promotion rules.
- `03-beta-playtest-protocol.md` — lightweight real-play evidence.
- `04-publication-surfaces.md` — Player Handbook, GM's Guide, and Bestiary plan.
- `05-cards-and-cardless-play.md` — material modes, host adapters, and shared
  operation contracts.
- `06-organismic-growth.md` — open membrane acquisition and witnessed becoming
  instead of class stacking.
- `07-session-and-table.md` — boot, active systems, resolution, pause, Rest, and
  return in a bounded Forgotten Realms session.
- `08-organism-chain-and-dynamical-systems.md` — multiscale bodies, active
  systems, zooming, consequence propagation, and bounded calculation.
- `09-unified-physics-and-delightful-play.md` — Gravity, Dark Matter,
  Antimatter, Bidirectional Recursion, entropy, phase, projection, care, and
  the table-facing rules for making them delightful rather than burdensome.
- `10-knowledge-language-and-culture.md` — perception, signal, memory, language,
  partial comprehension, provenance, and cultural sediment.
- `11-system-needs-and-build-order.md` — tiered system scope, required contracts,
  optional depth, and the beta implementation sequence.

## Release Boundary

The beta directory is design and acceptance material until the whole body passes
the graduation gate. A real beta release requires reports from real human table
play. Software simulations and internal walkthroughs may guide revisions, but
they cannot substitute for that evidence. The current Alpha 3 source remains the
authoritative released rules body, and the beta documents are not included in
the Alpha 3 publication build.
